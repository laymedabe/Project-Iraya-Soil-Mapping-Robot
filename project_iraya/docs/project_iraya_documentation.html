1 Introduction

Abstract

Project DUTA (Digitalized Unified Terrain Assessment) is a manually-operated, remote-controlled soil-mapping robot designed to collect and visualize geo-referenced soil nutrient data across agricultural fields. The robot is driven by an operator using an IR remote control; pressing the actuate button deploys the soil probe, reads NPK and related parameters, and automatically records the GPS-tagged measurement. The Raspberry Pi broadcasts its own Wi-Fi hotspot, so the web dashboard is accessible from any connected phone, tablet, or laptop — no internet connection is required. This document provides a complete technical reference for high school researchers building, operating, and extending the system.

1.1 Background & Context

Healthy soil is the foundation of productive agriculture. The three primary macronutrients — Nitrogen (N), Phosphorus (P), and Potassium (K) — directly influence plant growth, crop yield, and soil health. Traditional soil testing requires manual collection of soil samples, laboratory analysis, and several days of waiting. This process is labor-intensive, expensive, and produces data at too coarse a resolution to support precision agriculture — the practice of applying fertilizer and water only where and in the amounts that each zone of a field truly needs.

Advances in low-cost embedded electronics, wireless communication, and GPS technology now make it feasible for a student-built robot to perform the same type of geo-referenced, multi-point soil measurement that previously required professional equipment costing tens of thousands of pesos. Project DUTA was conceived to demonstrate this possibility and to serve as a working research platform for precision agriculture education.

1.2 Problem Statement

The core challenge addressed by Project DUTA is the spatial resolution problem in soil nutrient measurement. A single aggregate laboratory test for an entire field masks the significant variation in nutrient levels that exists even within a small plot. Without knowing where soil is deficient or excessive in a given nutrient, fertilizer applications cannot be targeted — leading to waste, runoff, and suboptimal plant growth.

Project DUTA enables researchers to manually drive the robot across a field using an IR remote, stopping at chosen locations to take in-situ NPK readings. At each stop, pressing the actuate button on the remote triggers the probe deployment automatically — extending the sensor into the soil, reading all seven parameters, and retracting — while the GPS coordinates are recorded. The Raspberry Pi then interpolates a continuous nutrient map from the collected measurements, viewable in real-time on any Wi-Fi-connected device.

2 Objectives

General Objective

To design, build, and validate a manually-operated, IR remote-controlled soil-mapping robot capable of collecting geo-referenced NPK, moisture, pH, electrical conductivity, and temperature readings at operator-selected field locations, and displaying the data as an interpolated nutrient map on a web-based dashboard accessible over a local Wi-Fi network.

Specific Objectives

  1. Hardware Integration: Interface a 7-in-1 RS485 Modbus NPK soil sensor, a NEO-M8 GPS module, and dual BTS7960 motor drivers with an Arduino Mega 2560 to create a unified real-time control layer.
  2. Safe Layered Control: Implement a two-tier control hierarchy (Arduino Mega for real-time hardware I/O and safety; Raspberry Pi 5 for mission planning, data storage, and web serving) with multiple independent safety watchdogs.
  3. One-Button Soil Sampling: Achieve a fully automated probe cycle triggered by a single IR remote button press — the robot stops, lowers the probe via a linear actuator, waits for the sensor to stabilize, reads all NPK parameters, and retracts the probe — without any further operator action during the ~24-second cycle.
  4. Real-Time Visualization: Display live sensor readings and a color-coded interpolated soil nutrient heat map on a web dashboard accessible from any browser on the field Wi-Fi network.
  5. Data Persistence & Export: Store all readings in a structured database (MariaDB on the Pi, with SQLite fallback) and support syncing data to a cloud database when an Internet connection is available.
  6. Multiple Control Modes: Support two control inputs — IR remote (primary field control) and an optional auto-cycle mode — while the web dashboard serves exclusively for real-time monitoring and mapping.

3 System Architecture

3.1 Layered Control Hierarchy

Project DUTA is built on a layered control principle: the system is divided into two distinct computational layers that communicate through a well-defined, line-based serial protocol. This separation provides reliability, safety, and maintainability — each layer only does what it is best suited for.

[Insert Lucidchart System Architecture Diagram Here]

The key design decision is that the Raspberry Pi never controls motors or the actuator directly. It sends only high-level text commands (DRIVE, STOP, SAMPLE) over the serial link. All real-time hardware I/O is handled exclusively by the Arduino Mega.

This separation was chosen for three reasons:

  1. Timing Guarantees: Python running on a general-purpose OS cannot reliably guarantee motor PWM timing under load. The Arduino Mega's bare-metal C++ loop has no such interference.
  2. Network-Independent Safety: If Wi-Fi drops while the probe is in the soil, the Arduino's onboard watchdog timer automatically stops all motion after 400ms — no command from the Pi required.
  3. Fault Isolation: A Flask crash or Pi reboot cannot leave the motors in a dangerous state, because the Mega enforces its watchdog timeout independently.

3.2 Raspberry Pi Wi-Fi Hotspot (No Internet Required)

A critical design feature of Project DUTA is that the Raspberry Pi itself acts as a Wi-Fi access point (hotspot) rather than connecting to an external network. This means the system is completely field-deployable with no internet connection required — ideal for use in remote agricultural areas where cellular or broadband coverage may be unavailable.

📶 How the Hotspot Works
  1. When the Raspberry Pi boots, it configures its built-in Wi-Fi adapter (wlan0) as a standalone access point using hostapd and assigns a static IP via dhcpcd or NetworkManager.
  2. The Pi assigns itself the address 192.168.4.1 and acts as a DHCP server for connected clients.
  3. Any device (phone, tablet, laptop) that connects to the Pi's hotspot SSID can immediately open a browser and navigate to http://192.168.4.1:5000 to access the live dashboard.
  4. The Flask application, database, GPS reader, and serial link to the Arduino all run locally on the Pi — the dashboard is fully self-contained.
ⓘ Note: Because the Pi's Wi-Fi is used as a hotspot, it cannot simultaneously connect to an external Wi-Fi router. Cloud sync (when available) requires either a USB 4G dongle or temporarily switching the Pi's network mode after the field session.

Arduino Mega — Firmware (arduino_mega/project_duta_mega/)

File Purpose
project_duta_mega.ino Main sketch. Orchestrates IR remote handler, serial command handler, actuator state machine, auto-cycle state machine, and E-STOP interrupt.

3.3 Communication Protocol

The Raspberry Pi and Arduino Mega communicate over USB serial at 9600 baud. All messages are plain-text, newline-terminated lines. This makes the protocol easy to debug with any terminal emulator.

Command / Message Direction Description
DRIVE <DIR> <speed> Pi → Mega Sets drive state. Direction: FWD, BACK, LEFT, RIGHT. Speed: 0–255. Must be resent every ~150ms as heartbeat; otherwise watchdog stops motors.
STOP Pi → Mega Immediate motor cutoff. Cancels auto-cycle if active.
SAMPLE Pi → Mega Triggers full sampling sequence: extend actuator → wait → read NPK → retract. Takes ~24 seconds total.
GOTO <lat> <lon> Pi → Mega Informational waypoint notification for logging.
START_AUTO Pi → Mega Starts the optional auto-cycle mode: drives forward 10s → stops → samples → repeats. Used on flat, unobstructed terrain when the operator chooses to enable it.
STOP_AUTO Pi → Mega Cancels auto-cycle, stops motors, returns to IDLE.
ACK <cmd> Mega → Pi Command received and accepted.
STATUS <state> Mega → Pi Current state: IDLE, MOVING, ALIGNED, LOWERING, READING, RETRACTING, AUTO_DRIVING, AUTO_SAMPLING.
DATA N=.. P=.. K=.. Mega → Pi NPK + moisture + temperature + EC + pH reading, once per completed SAMPLE.
FAULT <code> Mega → Pi Safety trip: ESTOP_TRIGGERED, ACTUATOR_BUSY, or AUTO_ALREADY_RUNNING.

3.4 Safety Layers

  1. Physical E-STOP Button — Wired directly into motor driver enable lines. Pressing it immediately cuts motor power regardless of software state. Non-negotiable for safe operation near people.
  2. Arduino Mega Watchdog (400ms) — If no fresh DRIVE command arrives within 400ms, the Mega forces all motors to zero. Entirely local to the Mega; does not depend on the Pi.
  3. Flask WebSocket Disconnect Handler — When the browser's WebSocket drops, the Pi immediately sends STOP. Typically faster than the 400ms watchdog, but is a convenience layer, not the primary safety guarantee.
  4. Actuator Time Bounds — The actuator sequence is time-bounded by constants in config.h. The Mega never drives the actuator beyond these limits, preventing mechanical damage even if the Pi stops sending commands.

3.5 Data Flow for a Sampling Session

Step 1 — Session Start

Operator clicks Start Session in the browser. Browser calls POST /api/session/start → Flask creates a sessions row and returns a session_id.

Step 2 — Navigate to Waypoint

Flask sends GOTO <lat> <lon> over serial, then streams DRIVE commands derived from GPS feedback to steer toward the target coordinates.

Step 3 — Sample Command

Flask sends SAMPLE. Mega acknowledges, stops motors, and begins actuator sequence: extend (7s) → hold and read NPK (10s) → retract (7s).

Step 4 — NPK Data Capture

During holding phase, the Mega queries the RS485 sensor via Modbus RTU. The 7-in-1 sensor returns N, P, K, Moisture, Temperature, EC, and pH. These values are printed over serial.

Step 5 — GPS Tagging & Database Write

The Pi's serial_comm.py background thread parses the sensor output, reads the current GPS position from gps_reader.py, then calls models.insert_reading() to write the geo-tagged measurement to MariaDB.

Step 6 — Map Update

Dashboard polls GET /api/map. Flask calls interpolation.py which applies IDW to all readings and returns a 50x50 grid. The browser renders this as a color-coded nutrient heat map.

Step 7 — Session End & Export

Operator clicks End Session. Flask sets status to completed and records the end time. Data can be synced to the cloud via scripts/sync_to_cloud.py.

4 Materials & Components

4.1 Hardware Components

🖥 Single-Board Computer
Raspberry Pi 5 (4GB or 8GB RAM)

Supervisory computing layer. Runs Flask, GPS reader, MariaDB, and Wi-Fi hotspot. Requires Raspberry Pi OS Bookworm 64-bit.

🤖 Microcontroller
Arduino Mega 2560

Real-time control layer. Manages all PWM motor signals, relay switching, RS485 Modbus, watchdog timer, IR remote, and E-STOP interrupt.

🔧 Motor Drivers (x2)
BTS7960 43A H-Bridge Module

High-current H-bridge driver for each side of the skid-steer chassis. Handles up to 43A continuous with built-in overtemperature and overcurrent protection.

🌿 Soil Sensor
7-in-1 RS485 Modbus NPK Sensor

Measures N, P, K (mg/kg), Moisture (%), Temperature (°C), Electrical Conductivity (μS/cm), and pH. Communicates via RS485 Modbus RTU through a MAX485 adapter.

📡 GPS Module
u-blox NEO-M8N (or compatible)

Provides NMEA sentences with latitude, longitude, altitude, satellite count, and HDOP. Achieves ~2.5m horizontal accuracy under open sky.

⚡ Probe Deployment
Linear Actuator + 2-Ch. Power Relay

The linear actuator physically inserts the NPK probe into the soil and retracts it. Controlled by a 2-channel active-LOW relay module on the Arduino.

📻 IR Remote Receiver
VS1838B (38kHz) + NEC Remote

Primary field control. Drives the robot Forward, Backward, Left, Right, Stop, and triggers the full Actuate (soil sample) sequence — all via the IRremote library (NEC protocol). Works entirely independently of the Raspberry Pi and requires no Wi-Fi connection.

🔴 Emergency Stop
Mushroom-head NC push button

Wired in series with motor driver enable lines. Hardware-level motor cut-off independent of all software. Non-negotiable for safe operation near people.

🔔 RS485 Adapter
MAX485 TTL-to-RS485 Module

Converts Arduino 5V UART to differential RS485 levels. A single DE/RE control pin manages bus direction. Connected to Arduino analog pins A2–A4.

🛤 Chassis
4WD Skid-Steer Rover Platform

Four-wheel-drive chassis with no steering linkage. Turning is achieved by driving opposite sides at different speeds. The drive_control.cpp module handles left/right motor mixing.

5 Instructions for Use

⚠ Safety First: Always test the E-STOP button before each operating session. Never operate the robot near people without a functioning E-STOP. Keep fingers and clothing clear of wheels and the linear actuator.

5.1 Hardware Setup & Connections

Connect Arduino Mega to Raspberry Pi

Use a USB Type-A to Type-B cable. Plug into any USB port on the Pi. The Pi identifies the Arduino as /dev/ttyACM0 (verify with ls /dev/tty*).

Connect motor drivers and motors

Left-side motors → BTS7960 Driver #1 (L_RPWM=D5, L_LPWM=D6, L_R_EN=D7, L_L_EN=D8). Right-side motors → BTS7960 Driver #2 (R_RPWM=D9, R_LPWM=D10, R_R_EN=D4, R_L_EN=D12). Connect 7–12V DC motor power to driver supply terminals.

Connect the NPK sensor and MAX485 adapter

MAX485: RO→A2, DI→A3, DE+RE (tied)→A4, VCC→5V, GND→GND. NPK sensor RS485 A/B lines → MAX485 A/B. Sensor power 12V → sensor VCC.

Connect the linear actuator relay

Relay: IN1→A0, IN2→A1, VCC→5V, GND→GND. Wire actuator leads through relay Common and NO terminals. Match relay supply voltage to actuator (typically 12V).

Wire and test the E-STOP button

Wire NC button in series with motor driver enable lines. Also connect one terminal to D3, other to GND (INPUT_PULLUP active). Press to confirm all motors stop immediately before operating.

Connect the GPS module

Connect NEO-M8 to the Raspberry Pi's serial port. Set GPS_PORT in .env (e.g., /dev/ttyS0). Ensure a clear outdoor view of the sky for GPS fix.

5.2 Flashing the Arduino Firmware

Connect Arduino to your development PC

Disconnect from Raspberry Pi first. Connect to laptop/PC via USB for programming.

Open the firmware sketch

Open arduino_mega/project_duta_mega/project_duta_mega.ino in Arduino IDE (v2.x recommended) or PlatformIO.

Review pin assignments in config.h

Verify all pin numbers match your physical wiring. This is the only file you should change to adapt to different hardware configurations.

Install required libraries

Arduino IDE: Sketch → Include Library → Manage Libraries. Install IRremote (by Armin Joachimsmeyer, v4.x) and TinyGPS++ if needed.

Select board and port, then upload

Tools → Board: Arduino Mega 2560. Tools → Port: select correct COM port. Click Upload and wait for "Done uploading."

Verify in Serial Monitor

Open Serial Monitor at 9600 baud. You should see the DUTA banner and STATUS IDLE. Reconnect Arduino to Raspberry Pi after verification.

6 Soil Nutrient Mapping Algorithm

Inverse Distance Weighting (IDW)

After collecting discrete NPK readings at GPS-tagged locations, the system must estimate nutrient values at all other points in the field to produce a continuous map. Project DUTA uses the Inverse Distance Weighting (IDW) algorithm, a standard spatial interpolation method widely used in precision-agriculture soil mapping literature.

Z(p) = Σ [ wi × Zi ] / Σ wi
where   wi = 1 / d(p, pi)2

Each known sample point pi with measured value Zi contributes to the interpolated value at p in inverse proportion to the square of the distance between them. Nearby samples have much greater influence than distant ones. A small epsilon (10−8) prevents division by zero when the grid point coincides exactly with a sample location.

Implementation Details

  • Grid resolution: 50×50 cells over the field's lat/lon bounding box.
  • Power parameter: 2 (standard for soil nutrient mapping).
  • Nutrients interpolated: Nitrogen, Phosphorus, Potassium (and optionally Moisture, Temperature, EC, pH).
  • Computation: Triggered on each GET /api/map request using Python/NumPy on the Raspberry Pi's CPU. Completes in well under 1 second for typical field sizes.

Nutrient Level Classification

Class Description Display Color
Low Value below the low threshold — soil may be nutrient-deficient. Blue / Cool
OK Value within the optimal range for typical crops. Green
High Value exceeds the high threshold — possible over-fertilization. Red / Warm

Note: Thresholds are illustrative and should be calibrated to the specific crop type and local agronomic standards for use in actual farming decisions.

7 Database Schema

All field data is stored in a relational database with four tables. MariaDB is used in production on the Raspberry Pi; the application automatically falls back to SQLite for development environments.

sessions — Field survey sessions

Column Type Description
id INTEGER PK Auto-incremented session identifier
field_name TEXT Human-readable field or location name
started_at DATETIME Session start timestamp
ended_at DATETIME Session end timestamp (NULL if still running)
status TEXT running | completed | aborted
lat_min/max, lon_min/max REAL Bounding box of the sampled area
notes TEXT Optional researcher notes
synced_to_cloud INTEGER 0 = not synced, 1 = synced to cloud DB

readings — Individual sensor measurements

Column Type Description
id INTEGER PK Auto-incremented reading identifier
session_id INTEGER FK References sessions.id
recorded_at DATETIME Timestamp of the measurement
lat, lon REAL GPS coordinates at time of reading
nitrogen REAL Nitrogen concentration (mg/kg)
phosphorus REAL Phosphorus concentration (mg/kg)
potassium REAL Potassium concentration (mg/kg)
moisture REAL Soil moisture (%)
temperature REAL Soil temperature (°C)
ec REAL Electrical conductivity (dS/m)
ph REAL Soil pH
altitude REAL GPS altitude (meters above sea level)
satellites INTEGER Number of GPS satellites in view
hdop REAL Horizontal dilution of precision

waypoints — Planned sampling points per session

Stores a sequence of target GPS coordinates planned for a survey session. Each waypoint can be marked visited=1 after the operator drives to it and takes a sample, allowing session progress to be tracked.

system_events — Operational log

Records fault conditions, connection events, and system messages with timestamps, severity levels (info, warning, fault), and the source component. Used for post-session analysis and debugging.

8 Troubleshooting

Symptom Likely Cause Solution
Motors do not move when drive buttons are pressed Wrong serial port, E-STOP engaged, or motor driver not powered Verify DUTA_SERIAL_PORT in .env. Check E-STOP (should be released). Confirm 12V supply to motor drivers. Check Arduino Serial Monitor for ACK DRIVE.
Actuator does not move on SAMPLE command Relay wiring reversed or active-HIGH relay used instead of active-LOW The firmware drives relay inputs LOW to activate. If your relay is active-HIGH, invert the digitalWrite values in actuator_control.cpp.
NPK sensor returns all zeros RS485 wiring error or incorrect Modbus address Swap the A and B lines between MAX485 and the sensor. Verify DE/RE pin (A4) is HIGH before transmitting. Check 12V sensor power.
GPS fix not obtained Poor sky view, wrong serial port, or cold start delay Move to open outdoor area. Allow 30–90 seconds for cold acquisition. Verify GPS_PORT in .env. Set GPS_SIMULATE=true for indoor testing.
Dashboard shows "Disconnected" or no readings appear Flask app not running, wrong IP, or firewall blocking port 5000 Confirm python run.py is running. Verify the Pi's IP address. Ensure port 5000 is open. Try accessing from the Pi's own browser first.
Robot keeps stopping every ~400ms Drive heartbeat not being sent fast enough Check browser console for WebSocket errors. The drive panel should send events every ~150ms while a button is held. Network latency may be too high.
MariaDB connection fails, app uses SQLite MariaDB not running or wrong credentials Run sudo systemctl status mariadb. Verify DB_USER, DB_PASSWORD, DB_NAME in .env. Note: SQLite fallback is fully functional for development.

9 Summary & Conclusions

Project DUTA demonstrates that a student-built, embedded robotic system can perform meaningful precision-agriculture soil analysis at a fraction of the cost of professional equipment. The key achievements of the project are:

What Was Accomplished

  1. Hardware-in-the-loop integration of five distinct hardware subsystems (motors, GPS, NPK sensor, linear actuator, and IR remote) into a single coherent robot platform, orchestrated through a clean layered software architecture.
  2. Real-time geo-tagged soil measurement: A single button press on the IR remote triggers the robot to insert the NPK probe, read seven soil parameters simultaneously, tag the measurement with live GPS coordinates, and retract the probe — all within a 24-second automated cycle requiring no further operator input.
  3. Spatial interpolation and visualization: Using IDW interpolation, discrete point measurements are transformed into continuous nutrient heat maps, enabling spatial patterns in soil health to be identified at field scale.
  4. Multiple redundant safety layers ensure the robot can be operated safely in open-air field environments, with hardware E-STOP, Arduino watchdog, and software disconnect handlers all working independently.
  5. Accessibility & field-readiness: The Raspberry Pi broadcasts its own Wi-Fi hotspot, making the web dashboard accessible from any phone, tablet, or laptop without an internet connection or external router. No app installation is required — any device with a browser can view live data and control the robot simply by connecting to the Pi's hotspot.

Limitations & Future Work

  • Navigation accuracy: Limited by ~2.5m GPS accuracy of consumer-grade NEO-M8. RTK GPS would enable more precise waypoint navigation.
  • Terrain adaptability: The 4WD skid-steer chassis suits flat terrain. Rocky, steep, or waterlogged fields require a different chassis design.
  • Battery monitoring: No automatic battery monitoring. Adding voltage sensing and low-battery return-to-base behavior would improve field reliability.
  • Sensor calibration: The 7-in-1 NPK sensor provides relative measurements that should be validated against laboratory analysis for quantitative agronomic use.
  • Multi-robot coordination: Scaling to larger fields could be achieved by running multiple robots in coordinated waypoint grids.
Key Takeaway for Researchers

The most important design principle in Project DUTA is the separation of real-time hardware control from supervisory software. By assigning the Arduino Mega full ownership of all time-critical, safety-critical hardware operations, and limiting the Raspberry Pi to mission planning and data management, the system achieves a level of reliability that a single-computer design could not. This principle — give each layer of a system only the responsibilities it can reliably fulfill — is fundamental to safe robotics engineering and applies to systems far more complex than Project DUTA.

10 References & Glossary

Glossary of Key Terms

Term Definition
NPK Nitrogen (N), Phosphorus (P), and Potassium (K) — the three primary macronutrients in soil.
IDW Inverse Distance Weighting — a spatial interpolation algorithm that estimates values at unsampled locations as weighted averages of known data points, with weights inversely proportional to distance.
Modbus RTU A serial communication protocol used in industrial devices. The NPK sensor exposes its registers over Modbus RTU via RS485.
RS485 A differential serial communication standard for long-distance, noise-resistant communication. Used for the NPK sensor link.
UART Universal Asynchronous Receiver/Transmitter — the serial protocol used for the Pi–Mega link and GPS module.
NMEA National Marine Electronics Association — standard sentence format used by GPS modules (e.g., GPRMC, GPGGA sentences).
PWM Pulse Width Modulation — controls motor speed by rapidly switching voltage on/off at a variable duty cycle (0–255 on the Arduino).
Skid-Steer 4-wheel-drive turning method where opposite sides are driven at different speeds. No separate steering mechanism needed.
BTS7960 A 43A H-bridge motor driver chip controlling direction and speed of a DC motor using PWM signals.
Flask A lightweight Python web framework used to serve the dashboard and REST API on the Raspberry Pi.
SocketIO A protocol enabling full-duplex, real-time communication between the browser and Flask server, used for live drive commands and status updates.
Watchdog Timer A safety mechanism that triggers motor stop if the expected periodic command does not arrive within a defined timeout window.
HDOP Horizontal Dilution of Precision — GPS accuracy measure based on satellite geometry. Lower values indicate better accuracy (1.0 is ideal).
EC Electrical Conductivity — measured in μS/cm or dS/m. Indicates dissolved salt concentration in soil. Used for salinity assessment.
Linear Actuator Electromechanical device converting rotary motor motion to straight-line motion — used to insert the NPK probe into soil and retract it.
Precision Agriculture A farming management concept based on observing and responding to within-field variability in soil and crops to optimize inputs at the finest possible spatial resolution.
